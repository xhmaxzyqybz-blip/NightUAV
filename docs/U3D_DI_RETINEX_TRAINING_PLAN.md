# U3D 原始 DI-Retinex 无监督训练前检查与方案

状态：仅方案，未启动任何训练；不等同于论文结果复现。依据 [源码学习笔记](DI_RETINEX_METHOD_STUDY.md) 和 EXP002 固定权重诊断。

## 必须分开的实验身份

1. 当前：LOL-v1 normal 官方预训练权重 → U3D，零参数更新，跨数据集推理。
2. 下一步原模型：相同网络/原始两项损失，在 U3D/train 随机初始化训练；不把官方权重作为默认初始化。
3. 可选独立实验：从 LOL-v1 权重微调 U3D。必须单列，不能冒充从头训练。
4. 后续损失改动消融：在第2项稳定后才比较；保持数据、预算、初始化和验证规则相同。

## 数据与隔离

实际目录：`datasets/U3D/lowlight/train` 800张，`val`100张。诊断清单选 train10 + val10，保留原划分；val样本永不参与反向传播。它们不是20张训练集，不能拼接用于训练。test/0901仅作EXP001实现审计，test全体禁止用于选参、早停或机制设计。

加载器应采用显式 manifest、图片扩展名白名单、RGB/[0,1]，返回 X/G/path。先验证全部 train/val 可解码、尺寸与非全黑，并在训练前做 SHA256 重复检查、缩略图近重复及场景/视频分组核查。本次完成900张缩略读取、20张选中图哈希唯一检查；没有据此声称训练/验证场景独立。若发现同一视频/近重复跨划分，记录并先确定分组协议，不静默搬动原文件。

## 原始协议与U3D适配

| 配置 | 代码原值 | 建议首次U3D试运行 |
|---|---|---|
| 网络 | normal, 3→64→64→6 | 不变 |
| 尺寸/裁剪 | 原图，无裁剪，无增强 | 保持完整视野、等比缩放到1280×720（16:9图）；非16:9保持比例、batch1；明确这不是原生4K论文协议 |
| 平滑目标 | uint8 OpenCV 9×9 sigma1.7→/255 | 先resize再同样blur；须记录此适配造成平滑物理尺度变化 |
| 数据增强 | 无 | 首轮无翻转/颜色抖动/随机裁剪 |
| batch/workers | 1 / 4 | 1 / 0（Windows先验证，之后再测worker） |
| 优化器 | Adam | lr1e-3, betas(0.9,0.999), eps1e-8, weight_decay1e-4；无调度器 |
| 梯度 | clip_grad_norm 0.1 | 使用clip_grad_norm_，记录裁剪前范数 |
| 损失 | RD+VS，系数1:1 | 不变，Gamma2.2、曝光Normal(0.5,0.001标准差) |
| 精度 | float32 | FP32起步，不先引入AMP |
| 初始化 | Conv weight N(0,0.02)，bias保留默认初始化 | 严格复刻；seed1149 |
| 训练预算 | 默认200轮，论文v1为1000轮 | 先20步→1轮；验收后再批准200轮上限；不直接跑1000 |

不先用256 patch作为“原模型”：图均值控制曝光比率，裁剪会改变目标分布。若720p训练仍OOM，停止记录峰值，再将640×360完整视野作为单列工程基线，不静默改batch或裁剪。

## 依赖、入口和保存

当前环境推理已通过。原训练导入 `cv2`、`natsort` 尚缺；本轮没有安装任何包。训练前选择安装兼容的小型依赖，或者独立复刻加载器；后者必须验证 GaussianBlur 边界、uint8取整及排序与原实现一致，不能用Pillow近似后声称完全一致。不得改torch/torchvision/CUDA。

在项目 scripts 创建独立训练入口（本轮不创建/执行），只读导入官方模型，不改第三方源码。显式路径、Windows __main__ guard、CUDA强制检查，发现全黑/NaN样本时报告并停止，不静默跳过。独立保存目录 `checkpoints/di_retinex/u3d_original_<run_id>/`，禁止覆盖官方权重；拒绝已有run目录。

每轮保存 last，验证改善保存 best，并每10轮存一份；保存 model/optimizer、epoch/global_step、随机状态、源commit、配置和数据清单hash。随机状态编码为可安全加载的基本类型/张量，检查 weights_only=True 恢复；模型导出另存纯state_dict。日志、图像在 experiments/<run>/outputs，JSON/CSV指标和配置可纳入Git；checkpoint始终忽略。

## 验证与提前停止（项目拟定，非官方）

- 每轮 eval + inference_mode，对全体val100做固定缩放评估，绝不优化；为可比的验证损失固定E=0.5，明确训练E是随机量。记录两项损失及总和，不以总和单独代表视觉质量。
- 同时报告输入/输出Y'均值、暗区与高亮比例、全白/任意通道饱和率、梯度与高频代理量；这些均非真正SNR/细节恢复指标。无配对GT，不计算PSNR/SSIM。检查固定val诊断图同坐标ROI，盲评可见细节/噪声/色偏。
- 预注册初始早停：至少20轮后，连续20轮验证总损失未相对改善0.1%则停止，保留 best 与 last；这是计算预算准则。出现非有限、输出退化或饱和率持续上升伴随视觉细节损失，立即人工复核，不称“损失更低效果更好”。锁定规则后不得用test修改。
- 此20张集为开发诊断集，结论有选择偏差；其结果不是独立泛化分数。正式方法比较需全val统计，并在模型和阈值冻结后才能一次性使用test。

## 8GB显存风险与执行闸门

EXP001 720p无梯度峰值已分配688.709MiB，不能外推为训练显存。单个4K的64通道FP32特征约2025MiB；反向需保存多层激活与梯度，原生4K训练显著有OOM风险。没有测得训练峰值或epoch时间，不虚构预计小时数。

待后续授权的最小步骤：

1. 完成缺失依赖和数据分组核查；固定manifest与配置。
2. 在train固定一图、全视野720p做前向+两loss+反向一步，检查有限梯度和CUDA峰值；不得使用test。
3. train跑20步短试验，验证checkpoint安全保存/恢复与原图hash；一次val前向，不据20步宣称收敛。
4. 通过后跑1轮，记录每步/数据加载/验证时间、显存、饱和率及固定ROI。
5. 人工确认后才批准较长训练；至少3个预注册种子（1149、1150、1151）的正式对照，记录失败运行和相同计算预算。
