# NightUAV 仓库复现审查

项目根目录为 `E:\NightUAV`。以用户指定的仓库为审查对象；未指定时根据当前目录确定，无法确定则询问路径。不要把此前审查过的仓库结论套用到新仓库。

## 操作边界

- 首先只读检查。除非用户明确授权相应动作，否则不修改或新建项目文件、不安装依赖、不下载大型文件、不启动训练、不删除文件。
- 默认通过静态阅读完成审查，不运行仓库脚本、导入仓库模块、启动推理或性能测试，以免触发下载、缓存写入或耗时计算。
- 报告直接回复用户，不自动写入仓库。最小复现路线仅供规划，不执行。
- 用户要求仅分析本地仓库时不访问外部链接。其他情况下，区分本地文件、远端已核实内容和未验证链接；不把链接存在等同于资源可用。

## 检查流程

1. 阅读适用的仓库指令和 README，记录方法名称、公开状态、安装说明、数据、权重、训练与推理命令。
2. 枚举实际主要目录和文件并说明用途。优先用 `rg --files` 和定向文本搜索，排除版本管理内部对象及庞大数据目录；不要只复述 README 目录树。
3. 逐项核实下表所列能力。检查入口调用链、导入、配置路径和资源路径，给出文件位置、关键符号及必要的行号。文件名不同不等于能力缺失；空文件、占位实现或指向缺失模块的入口不算完整实现。

| 检查项 | 核实重点 |
| --- | --- |
| 模型定义 | 网络结构、forward、增强计算、模型注册与必要的外部实现 |
| train | 实际训练入口、训练循环、优化器、调度器与 checkpoint 保存 |
| test / inference | 模型构建、权重加载、输入预处理、前向调用与输出保存 |
| dataset / dataloader | 数据读取、目录约定、划分、变换和批处理 |
| loss | 损失实现、组合与权重、训练时实际调用及导入依赖 |
| config | 配置文件是否存在，键名是否与代码和命令匹配 |
| pretrained weights | 实际权重或下载方式、对应模型与配置；识别 Git LFS 指针和占位链接 |
| evaluation | 质量指标、数据集汇总、效率测量及外部依赖是否形成完整流程 |

4. 判断自定义图片推理：能否传入任意单张图片或目录；核实格式、RGB/BGR、归一化、尺寸/分块限制、设备、checkpoint 和输出位置。区分增强网络与仅训练使用的增强模块、loss 或指标工具。仅缺简单图片读写封装时，明确说明可补齐的具体工作。
5. 判断 paired GT 依赖，分别报告训练、推理和评估：追踪数据返回值与 loss/metric 输入；区分成对正常光 GT、非配对正常光图像、伪标签和无 GT。评估使用 PSNR/SSIM 不自动意味着训练需要配对 GT；仅凭 README 的 unsupervised 标签不能定论。
6. 检查 README、requirements、environment、pyproject/setup、Dockerfile 和自定义扩展中的 Python、PyTorch、torchvision、CUDA、其他依赖版本。区分明确锁定、仅最低版本、未声明和代码兼容性推断。分开记录项目要求与本机已验证环境；未实际检查本机时写“未检查”，不推断 GPU/CUDA 可用性。
7. 列出 README、源码和实际目录结构的不一致，例如缺失入口/配置、参数名不符、数据路径冲突、缺失导入、权重结构不匹配或许可声明冲突。未运行验证的问题标为静态发现或待确认，避免声称已测试成功。

## 判定规则

先明确判定范围：默认覆盖完整论文方法的训练、推理和评估，同时单独说明单图推理是否可行。

- **A. 可以直接复现**：核心代码、入口、配置及必要资源获取方式齐全，未发现实质阻断；常规环境准备和按说明获取数据不算代码修改。只做静态审查时注明“静态判断，尚未运行验证”，不保证论文数值必然一致。
- **B. 少量修改后可以复现**：核心算法和所需资源已具备，仅需明确、局部的路径/配置/导入修复或简短入口封装。逐项说明修改；不能把重建网络、猜测训练方案、寻找未知权重称作少量修改。
- **C. 当前仓库不足以复现**：关键模型、训练流程、必要资源或实验协议缺失，或关键可用性无法确认到足以支持 A/B。区分已证实缺失与待核实，不把未知说成不存在。

没有预训练权重不必然阻止从头训练，但会阻止直接使用官方权重推理；不要求本来就不需要的模块（例如无训练算法的 loss）。按方法实际需要判断。

## 输出格式

用简洁中文输出，保留可点击文件路径和关键行号作为依据：

1. **结论**：A/B/C、判定范围和最主要原因；声明仅做静态审查及未执行事项。
2. **实际结构**：主要文件/目录与作用。
3. **复现能力表**：上述八项，状态使用“完整 / 部分 / 缺失 / 未核实 / 不适用”，附位置和阻断点。
4. **数据与推理条件**：自定义图片支持、训练/推理/评估的 paired GT 需求、数据与权重获取状态。
5. **环境与不一致**：版本要求、未声明项、文档与代码冲突。
6. **最小复现路线**：按依赖顺序列出补齐材料、准备环境、单图验证、数据集评估、必要时从头训练。缺少关键材料时先列获取材料，不编造可执行命令；标明哪些步骤需要用户另行授权。

报告可合并短项，但不能省略关键阻断依据。明确区分作者报告的论文结果与本次实际验证结果。
